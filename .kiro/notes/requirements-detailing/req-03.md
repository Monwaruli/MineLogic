### Requirement 3: Board Format Parsing and Printing

**User Story:** As the developer, I want one text format for Boards that both TypeScript and Python can read and write, so that generated, pre-computed, and hand-authored boards are interchangeable.

#### Acceptance Criteria

1. WHEN the Board_Parser receives text that breaks none of the rules in criteria 2 and 6, THE Board_Parser SHALL return the Board that the text declares. It SHALL read the width as the number of columns, the height as the number of rows, and each Tile as a zero-based row index followed by a zero-based column index. LF or CRLF line endings, a leading byte order mark, a missing line ending after the last line, blank lines, spaces or tabs at the start or end of a line, and the order in which Tiles are listed SHALL have no effect on the returned Board.
2. IF the text that the Board_Parser receives describes a Board with any of the following, THEN THE Board_Parser SHALL return no Board and an error that names a rule the text breaks. The rules are: a width or height outside 1 to 30; an identifier that is not 1 to 64 characters long or that contains a character other than an ASCII letter, digit, period, underscore, or hyphen; a mine, Start_Tile, or initially revealed Tile whose row index is outside 0 to height minus 1 or whose column index is outside 0 to width minus 1; a Tile listed twice among the mines or twice among the initially revealed Tiles; a Start_Tile that is a mine, has a mine among its Neighbors, or is declared together with an initial revealed set; an initially revealed Tile that is a mine; or neither a Start_Tile nor at least one initially revealed Tile. The error SHALL give the 1-based number of the line that holds the offending value. For every Start_Tile rule the offending value is the Start_Tile, and for a Tile listed twice it is the second listing. When the rule concerns a missing element, the error SHALL name the missing element instead of giving a line number.
3. WHEN the Board_Printer receives a Well_Formed_Board, THE Board_Printer SHALL write the Board's canonical Board_Format text. This text declares the current Board_Format version, the identifier, width, height, mine count, mine Tiles, and Start_Tile or initial revealed set in one fixed element order. It lists Tiles in ascending row-major order (by row index, then by column index) and contains only printable ASCII characters (codes 32 to 126) with LF line endings. It has no blank lines and no spaces at the start or end of any line, and it ends with exactly one LF.
4. FOR ALL Well_Formed_Boards, including Boards of every width and height from 1 to 30, Boards with zero mines, Boards with identifiers of 1 and of 64 characters, Boards with a Start_Tile, and Boards with an initial revealed set, printing with the Board_Printer, parsing the printed text with the Board_Parser, and printing the parsed Board again SHALL produce text identical to the first printing, and the parsed Board SHALL equal the original Board under Board_Equality (round-trip property).
5. FOR ALL text that the Board_Parser accepts, including text with the formatting differences listed in criterion 1, printing the parsed Board SHALL produce text that the Board_Parser accepts and that parses to a Board equal to the first parsed Board under Board_Equality. FOR ALL pairs of accepted texts whose parsed Boards are equal under Board_Equality, printing the two parsed Boards SHALL produce identical text (canonical-form property).
6. IF the text that the Board_Parser receives breaks any of the following rules, THEN THE Board_Parser SHALL return no Board and an error in the form given in criterion 2. The rules are: the text is empty or lacks a version, identifier, width, height, or declared mine count; it declares any of these or the Start_Tile more than once; it contains a non-blank line that the Board_Format does not define; it gives a width, height, mine count, row index, or column index that is not a whole number written in decimal digits; it declares a version that the Board_Parser does not support, which includes every version later than the current Board_Format version; or it declares a mine count that differs from the number of listed mines. For a repeated element the offending value is the second declaration, and for a mine count mismatch it is the declared mine count. Whenever the declared version is unsupported, the error SHALL name the unsupported-version rule, even if the text breaks other rules.
7. IF the Board_Printer receives a Board that is not a Well_Formed_Board, THEN THE Board_Printer SHALL write no text and SHALL return an error that names a rule of criterion 2 that the Board breaks.
8. FOR ALL Boards that the Offline_Generator writes, the Board_Parser SHALL accept the Board_Format text written for each Board, and that text SHALL be identical to the text that the Board_Printer writes for the parsed Board (cross-language property).
